# Validated browser actions

Phase 5.2 adds a strict proposal schema and `createFixtureActionExecutor(scope, policy, options)`. It is callable only against a trusted, disposable literal-loopback HTTP fixture. No production preview consumer or model loop is enabled. Run `npm run actions:verify` with Chromium installed; CI runs it after the existing browser installation.

The supervisor supplies an exact tenant/run/repository/PR/SHA policy, canonical origin, navigation paths, request path/method grants, target grants and synthetic values. Parsed policy snapshots detach caller mutations. Targets use exact accessible roles/names or labels and must match exactly one element. Proposals may navigate, click, fill, select, scroll or stop. Fill/select refer to supervisor-owned synthetic values; they cannot inject raw strings. Scripts, CSS selectors, uploads, arbitrary keys and coordinate actions are unsupported and rejected. Coordinate support requires a future viewport-bound policy rather than silently accepting pixels.

Target grants list permitted action kinds and value references. A target marked destructive requires explicit destructive permission and disposable data. This is trusted classification, not inference from button names: an incorrectly classified button or malicious same-origin page is outside the synthetic fixture guarantee. Unknown side effects cannot be inferred from accessible labels. Network mutations independently require an exact method/path grant with mutation permission and disposable data. Even GET can have side effects on an untrusted server; grants must be supplied by a trusted supervisor.

Every request checks current authority, exact origin/path/method and request count. Query strings, credentials, redirects, ungranted requests, subframe navigations and unlisted top-level navigation paths are denied. WebSockets, popups, dialogs, file choosers and downloads stop the browser; attachment responses are rejected before fulfillment. File inputs are rejected before interaction. Service workers are blocked. The fixture transport fetches responses without following redirects. These Playwright hooks are not a production network sandbox; response buffering, browser startup and shutdown still require external process/resource supervision for hostile targets.

Action count, request count, per-action deadline and session deadline are bounded. Actions and observations are serialized. Authority is checked before actions, immediately before target interaction, after actions and on requests. Cancellation/deadline abort closes the browser; failed or uncertain actions close the session and are never retried. Stop closes the session. Always call `close()` in a finally block even after a stop or failure.

`executed` means Playwright completed the requested interaction; it does not prove application success. Observe after execution to inspect resulting UI and diagnostics. Asynchronous requests can be blocked after a click has returned; the session then closes and further work is refused. Returned action records contain scope, sequence, fixed codes and counters, not synthetic values, page text or raw errors. Observations remain private untrusted fixture data under the Phase 5.1 contract.

Verification covers real accessible fill/select/click/scroll/navigation, created fixture state, malformed and destructive proposals, redirects, denied network mutation, file input refusal, action exhaustion, stale authority and scope mismatch. Production isolation, credential injection, durable budgets/artifacts, generic destructive-operation detection and the model adapter remain future phases.
