# Browser observation

Part 5.1 follows the small-phase roadmap: observation only; validated exploratory actions belong to 5.2. `createBrowserObserver` collects a private record from a trusted source; `fixtureObservationSource(page)` uses the installed Playwright `locator.ariaSnapshot` and viewport PNG screenshot APIs. The source never navigates or executes page instructions. It is intended only for trusted synthetic fixture contexts, not customer previews.

Create the observer before scripted navigation, call `markAction` with a non-sensitive internal action ID, call `observe` after the scripted step, and close the observer in a `finally` block before closing the owning browser. Observation does not own or close the browser. The existing smoke fixture driver accepts a trusted page instrumentation hook for this integration. Its existing origin, redirect, popup, download and WebSocket restrictions remain in effect; no new action or navigation authority is granted.

Records bind tenant, run, repository, PR and immutable SHA. They include an observation sequence, action marker, monotonic start/end times, accessibility-oriented text, PNG bytes and diagnostic metadata. Console errors, page exceptions, failed requests and HTTP 400–599 responses have ordered sequence numbers, elapsed times and the currently active action marker. Raw messages, stack traces, URLs, headers and bodies are omitted from diagnostics. Delayed events can outlive an action: markers are temporal correlation, not causation. Events are cumulative, so consumers must deduplicate by sequence within the session. HTTP errors are observations, not automatic bug findings.

Snapshots can contain text, field values and malicious instructions from the page. Screenshots mask inputs, textareas, selects and elements marked `data-dogwatch-secret`; that is not general secret redaction. Both capture types are private, untrusted synthetic-fixture artifacts. They must not be published or passed directly to a model. This phase returns bytes in memory and does not add persistence, model prompting, a public artifact route or a claim of accessibility compliance.

Limits cap observations (default 20, maximum 100), retained diagnostic events (200/1000), snapshot UTF-8 bytes (16/64 KiB), screenshot bytes (512/1024 KiB), and each combined capture deadline (1/5 seconds). Overflow produces explicit gaps and dropped-event counts; oversized captures are omitted rather than silently truncated. Captures are sequential and overlapping calls are refused. Authority is checked before and after collection; cancellation, stale scope, a failed authority callback or deadline withholds both captures and closes the observer. Closing detaches listeners idempotently.

Limits bound returned data and waiting, not browser CPU or temporary allocation during capture. A promise timeout cannot kill arbitrary source work. The trusted supervisor must close the browser and enforce process/session budgets. Page snapshots and screenshots are sequential, not atomic. Production browser isolation, whole-run budgets, remote capture routing and private artifact persistence remain pending; normal worker startup remains dispatch-only.

Run `npm run observation:verify` for real Chromium verification against a disposable loopback page. It proves accessible content, a PNG, updated state, action-linked console/exception/network diagnostics, and 404/500 capture. Chromium must already be installed (`npx playwright install chromium`). CI runs this after its existing Chromium installation. Unit tests cover data limits, immutable returned buffers/events, stale authority, cancellation, timeouts, closure, concurrency and observation count.
