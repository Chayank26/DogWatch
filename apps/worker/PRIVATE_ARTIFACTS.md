# Private finding artifacts

Phase 6.3 adds a callable local adapter in `src/private-artifacts.ts`. It stores references compatible with the v2 finding contract and keeps its files under `findings-v2/<tenant>/<run>/`, separate from the earlier smoke-evidence format. It introduces no public route, signed URL, cloud bucket, database migration or production consumer.

`persistPrivateArtifact(root, trustedScope, content)` accepts a version-1 content envelope: kind, `contentPolicy: reviewed_redacted`, creation/expiry timestamps and either `{ format: json, value: ... }` or `{ format: png, base64: ... }`. Screenshots require PNG form; other supported finding artifact kinds require JSON. The producer must review/redact content before storage. Kind and redaction labels are attestations, not proof, secret detection or semantic validation of API/browser/replay findings.

JSON must be a bounded plain tree with finite numbers, no unsupported values/cycles/unsafe property names, depth at most 16 and at most 10,000 visited nodes. Content is limited to 2 MiB of serialized UTF-8; screenshots have a 1 MiB decoded limit, canonical base64 and PNG signature checking. Signature checking is not complete image decoding or visual safety validation. Payloads are detached before asynchronous filesystem work. Expiry must follow creation by at most seven days; future-created or already-expired writes are refused.

The adapter uses mode-0700 directories, mode-0600 files, exclusive no-follow temporary files, file sync, and non-replacing hard-link publication followed by directory sync. A per-run lock serializes writers and a 50-artifact quota bounds publication. Existing locks are not stolen. Crashed writes may require operator reconciliation of lock/temp/complete-but-unreturned files. This local adapter assumes an operator-owned root parent and no hostile concurrent process changing private directories. It does not provide an OS sandbox, encryption at rest or cross-host distributed locking.

`readPrivateArtifact(root, trustedScope, reference)` validates exact tenant/run/repository/SHA/role and UUID, refuses unsafe directories/symlinks/permissive files, reads within a fixed byte ceiling, verifies the saved envelope's size/hash/kind/expiry and requires every supplied reference field to match storage. Expired artifacts cannot be read normally. Returned content remains private and untrusted; never render stored strings as executable markup or code.

`verifyFindingArtifacts(root, finding, trustedContext, authorize)` first validates the v2 finding, then calls the required authorization callback separately for every head and base reference before reading it. The callback receives detached metadata and must resolve actual access from trusted application state. A base reference in a finding is not authorization to read another run. The function rechecks expiry/context structure after asynchronous work and returns the finding, verified artifact IDs, `verification: references_verified`, and `semanticVerification: not_performed`. It does not return raw payloads or promote finding confidence. Authorization revocation/current-head reconciliation remains the supervisor's responsibility.

`prunePrivateArtifacts(root, trustedScope)` removes only validated expired records matching that exact scope. It leaves other SHA/role records untouched, ignores unrelated file names, and refuses malformed/tampered objects rather than deleting uncertain data. Retention pruning is an explicit trusted call, not a background scheduler or permission to remove a run directory. Evidence expiry therefore remains enforceable even before physical pruning.

All direct storage scopes and roots must come from an authorized supervisor, never directly from public request bodies. Hashes detect mismatch against trusted references; they cannot defend against an operator who can rewrite both storage and trusted references. Artifact existence/integrity alone does not prove an application defect or baseline comparability. A later aggregator must inspect evidence contents before reporting claims.

Tests use real temporary filesystem storage for roundtrips, permissions, snapshots, cross-scope/reference refusal, tampering, symlinks, expiry, scoped pruning, quota/locks, size/complexity constraints and independent base-reference authorization. Hosted object storage, authenticated download endpoints, durable catalog/recovery, typed producer adapters and report publication remain future integration work.
